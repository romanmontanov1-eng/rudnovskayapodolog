# Проверка публикации, 27 ноября 2026

## Подтверждённые дефекты

До исправления `submit()` выставлял `sending` до завершения локальной подготовки. Ошибки подготовки и исключения нативного `fetch` попадали в общее сообщение «Ответ потерян». Вызов `fetch` сам по себе не доказывает, что HTTP-запрос покинул браузер: сериализация тела тоже может завершиться отказом до сети. Поэтому отсутствие POST в Cloudflare согласуется с таким отказом, но не устанавливает конкретное исключение на устройстве Ольги.

Физический iPhone и его журнал ошибок недоступны. Нативный сбой сериализации воспроизведён управляемой инъекцией в WebKit; утверждения, что Safari вообще не поддерживает FormData, здесь нет.

## Исправление

- Проверка названия, обеих фотографий, постоянного ID, operation, revision и visible происходит до отправки.
- Фото преобразуются из Blob в бинарный снимок черновика. Multipart собирается заранее в Uint8Array, включая UTF-8 поля и два JPEG-файла. Нативному fetch больше не передаются FormData/Blob. Серверный протокол остаётся прежним.
- Предварительное создание Request и сохранение подготовленного черновика завершаются до dispatch. Для передачи уже подготовленного снимка исправлен порядок регистрации задания в очереди persist.
- Отдельные стадии: validate, snapshot, multipart, request-build, draft-save, dispatch, response, cleanup. Локальная ошибка приводит к not-sent и явному сообщению «Работа не отправлена на сайт», с кодом стадии. Поля и фото остаются в форме; результат сохранения черновика сообщается отдельно.
- Отказ после вызова fetch без ответа означает unconfirmed: браузер не может достоверно отличить отказ до сети от потерянного ответа. Operation сохраняется для безопасного повтора. Полученный HTTP-ответ и подтверждённое сохранение учитываются отдельно.
- Позднее завершение фонового сохранения фото не перезаписывает сообщение публикации. Кнопки освобождаются в finally.
- Консоль содержит только фиксированные названия стадий, коды, имя класса исключения из разрешённого списка, HTTP-статус и флаги попытки/ответа. Названия работ, фото, тела запросов, произвольный текст исключений, пароли и секреты не логируются.

Авторизация, cookies, Origin, серверный GitHub token flow, дизайн и исходные публичные страницы не изменены. worker.mjs пересобран из исходников.
