# Работы Ольги

Один существующий кабинет на Cloudflare Worker; база данных, Pages CMS и платная подписка не нужны. Бело-голубой мобильный интерфейс сохранён. Изменения продолжаются в `olga-gallery-editor`, PR №1.

## Данные и публикация

Единый каталог `assets/data/works.json`: постоянный ID, название, ссылки на оба файла, видимость, дата создания, ревизия и ID выполненных операций. Шесть существующих пар имеют ID `case-1`…`case-6`; их SVG-файлы оставлены без изменения, поскольку содержат исходное кадрирование. Старые и новые пары используют один серверный путь редактирования. Новые ID создаются до первой отправки и сохраняются в локальном черновике.

Новые снимки: браузер декодирует ориентацию, сохраняет пропорции, рисует в sRGB без фильтров, уменьшает длинную сторону до 1600 px и кодирует JPEG. В репозиторий отправляется только подготовленный файл до 1,4 МБ, без EXIF исходника. Браузер должен уметь читать выбранный формат. Если HEIC не декодируется, предлагается JPEG/PNG, остальные поля остаются. Локальные черновики хранят Blob, прежние data URL мигрируют в Blob. В каталоге нет base64 фотографий. JPEG — сжатие с потерями, не ретушь; возможны обычные различия цветопередачи между экранами.

Сервер создаёт Git blobs для фото и готовых `index.html`, `works.html` и каталога, затем дерево и коммит. Единственное non-force обновление ref публикует весь набор атомарно. При конфликте перечитывается ветка; изменение той же работы проверяется по ревизии. ID операции и хеш запроса обеспечивают повтор без дубля, в том числе после потери ответа. Замена одного снимка сохраняет ссылку на другой. Снятие с показа меняет visible, а не удаляет историю или файлы.

Главная содержит первые две видимые работы и переход в полную галерею. Страницы генерируются в серверном коде, Liquid не требуется. Проверка способа действующей сборки: GitHub Actions run 38737118439, main 3eb2d08, success, build job 116429135989 содержит «Build with Jekyll», затем upload artifact и deploy. Ранее `_data/gallery`/Pages CMS не используются.

После API-успеха показывается «Сохранено в репозитории». Отдельная кнопка проверяет публичную works.html на ID/ревизии всех видимых работ и отсутствие скрытых. Только совпадение даёт «Изменения уже появились на сайте». Тестовая ветка всегда сообщает, что действующий сайт не изменён.

## Запуск

1. Сначала принять PR №1 в main: кабинет требует каталог и маркеры WORKS в обеих страницах. Убедиться, что GitHub Pages успешно обновился и сохраняет шесть работ.
2. Локально установить актуальный Wrangler, из корня выполнить `node _cabinet/build.mjs`. Исходники интерфейса — `_cabinet/index.html`, app.js, app.css; worker.mjs генерируется.
3. Из `_cabinet` выполнить `npx wrangler secret put ADMIN_PASSWORD`, затем `npx wrangler secret put GITHUB_TOKEN`. Вводить значения только в терминале или панели Cloudflare, не в чате. Пароль — длинный случайный. Fine-grained GitHub token: только этот репозиторий, Contents read/write. Секреты не должны попадать в vars, Git или клиентский JS.
4. `npx wrangler deploy`. Имена переменных и лимит попыток входа заданы в wrangler.toml. Токен должен иметь право отправлять коммиты в выбранную ветку; ограничения protected branch нужно проверить перед рабочей публикацией.
5. Передать Ольге HTTPS URL и пароль приватно. В Safari: Поделиться → На экран Домой. Вход — пароль, подписанная 12-часовая HttpOnly Secure SameSite=Strict cookie; смена пароля отзывает старые cookie. Изменения требуют входа и совпадающего Origin. LOGIN_LIMITER ограничивает попытки входа (5/мин на IP, лимитер Cloudflare действует в своём размещении).

Для отдельного тестового Worker выполнить secret put для обоих секретов с `--env staging` и `npx wrangler deploy --env staging`. Его GALLERY_BRANCH = olga-publication-test, main не затрагивается. Не использовать тестовый пароль из dev.mjs в рабочем Worker. dev.mjs — только локальный стенд с памятью вместо GitHub, не production entrypoint.

## Проверки

`node _cabinet/tests/publication.test.mjs` — шесть тестов: полный цикл, повтор/потеря ответа, ревизии и неполная пара, управление старой работой и обмен снимками, вход/cookie/Origin/401, статусы pending/live/staging, порядок Git API и экранирование HTML. Фикстуры — искусственные одноцветные JPEG в tests/fixtures, не фотографии клиентов.

`npm run dev` — изолированный локальный стенд. Тестовый пароль: olga-test-stand. `/stand/works.html` и `/stand/index.html` показывают результат только в памяти. Ни токена, ни сетевой записи GitHub нет. В dev.mjs Secure cookie снимается только для локального HTTP; рабочий Worker всегда использует Secure.

В managed-среде preview остановлен: EPERM на прослушивании 4173. Поэтому браузерная проверка выбора фото, ширины iPhone, Safari/HEIC, EXIF и цветового профиля фактически не выполнена. Её нужно провести на HTTPS staging: войти, выбрать два тестовых снимка из Фото, проверить подписи/ориентацию, обменять, заменить один, перезагрузить черновик, опубликовать, переименовать, заменить один, снять с показа; проверить отсутствие теста на основном сайте.

Рабочий Cloudflare Worker не развёрнут и реальные секреты не установлены в этой сессии: подключение Cloudflare недоступно. Финальная проверка GitHub Pages после слияния и запуска остаётся обязательной.
